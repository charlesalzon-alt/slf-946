Hinweise zum Testen Test- & Demo-Werkzeug
  • Was ist das? Outbound-Trigger für den Wüstenrot-Finanzierung-Agenten. Beim Absenden des Formulars startet ein echter ElevenLabs-Anruf über den PriceHubble-n8n-Flow.
  • Microsite vs. Prototyp. Bei einem echten Microsite-Anruf liefern die PriceHubble-Lead-/Dossier-APIs sowohl lead_id als auch die Kundenidentität automatisch. Aus diesem Prototyp werden beide Werte manuell eingetragen. Variablen aus Custom Records (financing_with, months_to_expiry) sind nur dann gefüllt, wenn das Dossier in PriceHubble existiert und ein Loan-Custom-Record gepflegt ist.
  • lead_id ist wichtig. Stark empfohlen: eine echte lead_id eintragen (das Feld ist mit unserer Test-Lead vorbefüllt). Ohne lead_id fällt n8n auf Dossier-URN-Lookup oder Create-Lead zurück — beides funktioniert, bildet aber das Microsite-Verhalten nicht ab.
  • Bei DSW (Inbound Leads / Partner-Tipps) ist die lead_id nicht relevant — der Anruf reagiert auf einen neu eingegangenen Tipp, nicht auf einen bekannten Kontakt. Lassen Sie das Feld leer, n8n verwendet den Create-Lead-Branch.

Agent Instructions & First Message

The agent prompt and the first message the agent says are now managed centrally in the n8n trigger workflow (Hardcoded Templates Set node, workflow AxjAwu0ZwKvcgw8Z) and cannot be edited from this sandbox. The knowledge base is always included separately — view knowledge base.

Call Details

Customer and advisor information used during the call. These values are automatically inserted into the agent's script.

PB owner template 8.2 ships this from user.get.firstName. The n8n flow concatenates with the last name into the resolved {{advisor_name}} dynamic variable.

PB owner template 8.2 ships this from user.get.lastName.

Required for the new architecture: n8n calls Get Lead Details to resolve title / customer_first_name / customer_last_name. If empty, n8n falls back to the prototype-style Create Lead chain with empty identity (agent's First Message collapses to the self-intro-only template).

Leer lassen → n8n fällt auf Dossier-URN-Lookup oder Create-Lead zurück. Für sauberen Microsite-Test eine echte lead_id verwenden.

PB owner template 8.2 ships this from {{context.urn}}. n8n's Normalise Dossier ID Code node validates the URN format and the Get Custom Records by Dossier HTTP node uses the extracted UUID to fetch the dossier's custom records. From v3.17, financing_with and days_to_expiry (→ months) are resolved from value.loans[0].bank / value.loans[0].remainingTermDays on that response. Prototype-fired calls (which hit a non-PH dossier or no dossier) fall through to the "unknown / ASK Q1+Q2" branch. A leading dossier_id: prefix is stripped defensively.
